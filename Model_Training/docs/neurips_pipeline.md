# LENS 流水线：从数据收集到模型训练

本文档概述了针对 NeurIPS Datasets & Benchmarks 赛道提交的完整端到端流水线：**PrismBench**（数据集）和 **LENS**（评估指标模型）。

## 🎯 核心动机：填补 CLIP 与 DINO 的多主体评估鸿沟 (Bridging the Gap)
现有的主流评估指标（如 CLIP Score 和 DINOv2）在单主体生成中表现良好，但在多主体生成（N>=2）时存在严重的“语义捷径 (Semantic Shortcut)”和“特征坍塌盲区”：
1. **CLIP 的盲区 (全局词袋效应)**：CLIP 倾向于全局语义匹配。如果 Prompt 是“A打B”，哪怕模型生成了“A和B握手”（语义错位 Class 3），或者“A的衣服颜色染给了B”（特征泄漏 Class 2），CLIP 依然会给出高分。它无法察觉局部属性的错乱和张冠李戴。
2. **DINOv2 的盲区 (密集场景失效)**：DINOv2 擅长像素级匹配，但在极端密集场景（如 N=8）或严重遮挡时，它往往无法准确数出主体数量，也无法诊断主体是否同质化（克隆人），从而掩盖了严重的实体崩溃（Class 4）。

**LENS 的使命**：重新审视多主体个性化生成的评价标准，通过引入包含“特征泄漏”和“语义错位”的细粒度诊断架构，彻底覆盖 CLIP 和 DINO 留下的学术空白，确保评估结果真正对齐人类视觉感知。

## 阶段 1：数据收集与生成 (PrismBench)

为了训练一个鲁棒的指标模型，我们需要一个包含多种失败模式的、大规模且多样化的多主体生成图像数据集。

### 1.1 源主体库与 Prompt 自动构建 (多模型协作引擎)
为了实现 11 万条数据的自动化规模，我们构建了一个基于顶尖大模型的多代理协作流水线：
*   **参考图生成 (Reference Generation by GPT)：** 使用 **GPT-4o / DALL-E 3** 根据预设的主体类别，生成高质量、纯白背景的单主体参考图 (Reference Images)。GPT 负责把控主体的视觉多样性和特征清晰度。
*   **场景编排 (Prompting by Claude)：** 使用 **Claude 3.5 Sonnet (或 Opus)** 接收 GPT 生成的主体列表，并组合生成多主体同框的复杂 Prompt。Claude 在长文本逻辑推理和复杂场景编排上具有卓越能力，能确保交互动作合理且极具挑战性。

### 1.2 场景设计：自顶向下的降维策略
构建能够强制多个主体出现在同一场景中的 Prompt。**主体数量 $N$ 的取值范围严格设定为 2, 4, 6, 8**（剔除 N=1，因为单主体生成已不是学术难题，PrismBench 专注于纯粹的“多主体特征纠缠”）。
*   **降维生成策略 (Top-Down Prompting)：** 
    1.  首先让 **Claude** 设计包含 **8 个主体**的最复杂场景 Prompt。
    2.  随后，通过让 Claude 逐步剔除主体，向下缩减生成 **6、4、2** 个主体的 Prompt。
    3.  这种格式确保了场景语义的连贯性，并能精确控制主体数量的衰减测试。
*   **场景类型 (Scene Types)：**
    *   *中性 (Neutral)：* 主体空间分离（低特征纠缠风险）。
    *   *遮挡 (Occlusion)：* 主体前后遮挡（中等特征纠缠风险）。
    *   *交互 (Interaction)：* 主体物理接触（高特征纠缠风险）。

### 1.3 图像生成（成对数据生成）
使用构建好的 Prompt 和参考图像，生成成对的图像，以捕获质量差异和失败类型：
*   **强模型 / 好的图片 (Strong Model)：** 使用 **[Gemini 图像生成大模型 (Nano Banana 2)](https://gemini.google/overview/image-generation/)**。作为当前 SOTA，它预期能生成构图完美、特征无泄漏的高质量图像。
*   **弱模型 / 差的图片 (Weak Model)：** 使用 **MOSAIC**。作为基线模型，预期在极端数量 (如 N=8) 或复杂交互下会产生特征泄漏和实体崩溃。
*   *关键规则 (Crucial Rule)：* 对于每一个 Prompt，必须**同时**使用 Gemini 和 MOSAIC 生成图像。因为 Prompt 相同，背景语义得到控制，从而孤立出主体生成的质量差异。

## 阶段 2：标注与分类体系设计 (VLM 伪标签与人工标注)

我们采用“蒸馏用于训练，人类用于测试”的策略，预计构建 11 万条规模的评测数据集：
*   **自动标注 (Auto-labels)：** 约 **100,000 (10w)** 条数据由强大的 VLM（如 Qwen3.5-35B-FP8）自动打标，作为训练集 (Silver Set)。
*   **人工标注 (Human-labels)：** 约 **10,000 (1w)** 条数据由人类专家严格标注，作为测试集 (Golden Set)。

### 2.1 6类层级化错误分类体系与三级打分制 (3-Tier Scoring)
LENS 的核心在于诊断多主体生成**为什么**失败。加上将“实体崩溃”拆分为“缺失”与“崩坏”，我们构建了一个完美的 6 类互斥（MECE）决策树。

为了解决生成图像中常见的“模棱两可”情况，我们引入了**三级打分制 (3-Tier Scoring System)**，为每个错误类别分配：
*   **`1.0` (是 / Yes)**: 明显存在该类错误。
*   **`0.5` (可能 / Maybe)**: 存在轻微瑕疵、部分被遮挡难以判断、或者人类也需要仔细辨认的模棱两可状态。
*   **`0.0` (否 / No)**: 完全不存在该类错误。

系统按以下严重程度顺序（从上往下过滤）评估，遇到第一个非 `0.0` 的类别即作为主要错误分类，**这种“瀑布流”判定法彻底消除了分类歧义**：

*   **Class 5: 核心实体缺失与同质化 Subject Omission & Homogenization (最严重：存在性失败)**
    *   *判断条件：* 画面中是否恰好存在请求的 $N$ 个独立的**核心参考主体 (Reference Subjects)**？
    *   *打分示例：* 
        *   `1.0`: 
            - **明确少人**：要求参考主体A（猫）和B（狗），画面只有狗，猫完全消失。
            - **同质化克隆**：要求参考主体A（美队）和B（钢铁侠），生成了两个一模一样的钢铁侠。
            - **物种变异消失**：要求A（人）和B（猫），结果画出了两个人，猫没有了。
        *   `0.5`: 
            - **严重遮挡或残缺**：核心主体在画面边缘被严重裁剪，只露出半张脸或一只手，很难辨认身份。
            - **极度模糊**：主体在远景中模糊成一团像素，无法确切核实是否是指定的参考主体。
    *   *🚫 防歧义边界：* **只清点“必须通过 Reference Image 定制”的核心主体。**如果 Prompt 里随口提的一个纯文本配角（如“一个路人”）或道具（如“一把椅子”）没画出来，**不属于** Class 5，请继续往下走到 Class 1 扣分。
    *   *对标现有指标：* **DINOv2 / Object Detection / CLIP-I** (侧重数人头和特征召回)。

*   **Class 4: 实体结构扭曲与崩坏 Subject Distortion & Mutilation (次严重：结构性失败)**
    *   *判断条件：* 在 $N$ 个主体都存在的前提下，是否有主体的**基础生物/物理结构**发生了严重的扭曲、残缺或畸变？
    *   *打分示例：* 
        *   `1.0`: 
            - **肢体恐怖变异**：美国队长长了三个胳膊，或者脸部像融化的蜡像一样完全扭曲。
            - **身体严重残缺**：钢铁侠在画面里，但只剩下一个悬空的头，身体躯干凭空消失了。
            - **非人物理结构崩坏**：如果主体是一辆汽车，汽车只有三个轮子或者车身折叠成了违反物理常识的形状。
        *   `0.5`: 
            - **轻微比例失调**：美队的腿看起来异常短小，或者手部手指有6根但整体还能认出是个人。
            - **轻微的人体结构不对齐**：脖子和身体的连接处稍微有些生硬。
    *   *🚫 防歧义边界：* **专门惩罚画成了“怪物”的模型。**它与串色（Class 2）绝不重合。美队自己长了三个胳膊（结构破坏）是 Class 4；美队结构完美，只是衣服染上了钢铁侠的红色（颜色转移）是 Class 2。
    *   *对标现有指标：* **FID / IS (Inception Score) / IQA metrics (如 BRISQUE)**。

*   **Class 3: 语义错位 Semantic Swapping (属性绑定错误)**
    *   *判断条件：* 不同的主体是否被**错误地分配**了属于彼此的角色、动作或一整件物品？
    *   *打分示例：* 
        *   `1.0`: 
            - **动作张冠李戴**：要求A骑马B牵马，生成了B骑马A牵马。
            - **整套衣服互换**：要求A穿红裙B穿蓝裙，生成了A穿蓝裙B穿红裙。
            - **核心道具拿错**：要求A拿剑B拿盾，生成了A拿盾B拿剑。
            - **位置关系互换**：要求A站在桌子上，B坐在椅子上，结果变成了B站桌子上，A坐椅子上。
        *   `0.5`: 
            - **动作不标准或位置关系模糊**：要求“背靠背”，但看起来像“并排站”或“一前一后”。
            - **道具归属不清**：A和B中间放着一把剑，看不出到底是谁拿着。
    *   *🚫 防歧义边界：* **前提是“元素确实画出来了，但给错人了”。** 如果要求A拿剑，但画面里**根本没画出剑**，那不叫错位，叫彻底遗漏，去 Class 1 扣分。
    *   *对标现有指标：* **VQA / T2I-CompBench**。

*   **Class 2: 特征泄漏 Attribute Bleeding (局部串色/材质污染)**
    *   *判断条件：* 核心身份和动作是否正确，但局部特征（颜色、配饰、肢体特征）在主体之间泄漏？
    *   *打分示例：* 
        *   `1.0`: 
            - **明确的局部串色**：美队蓝色的制服上出现了钢铁侠的红色金属材质斑块。
            - **身体结构融合**：两个人握手时，手部融合成了一坨带有双方肤色的肉块（没有变成怪物，只是肤色和材质融合）。
            - **配饰传染**：A戴着墨镜，B没戴，但生成的图片里B的脸上隐约出现了墨镜的边框或镜片反光。
            - **发色泄漏**：A是金发，B是黑发，结果B的黑发里夹杂着一缕金发。
        *   `0.5`: 
            - **边缘接缝处的颜色渗透**：两个主体站得很近，衣服边缘有轻微的颜色相互渗透。
            - **疑似环境光污染**：看起来像串色，但也可能是环境光影反射导致的模棱两可状态。
    *   *🚫 防歧义边界：* **这是“像素污染”，不是“整件衣服穿错”。** 如果 A 的红衣服直接套在了 B 身上（B穿红衣服），那是 Class 3。如果 A 和 B 都穿对了衣服，但 B 的蓝衣服上有一大块红色色斑，那才是 Class 2。
    *   *对标现有指标：* **无有效的全局指标**（LENS 独家贡献，CLIP 完全盲区）。

*   **Class 1: 文本遗漏与动作不对齐 Prompt Misalignment / Omission**
    *   *判断条件：* 在所有**核心参考主体**都已完美出现（过了Class 5/4）、未穿错衣服拿错道具（过了Class 3）、未串色（过了Class 2）的前提下，画面是否完全遗漏了 Prompt 要求的**交互动作、状态或纯文本指定的普通道具（非定制主体）**？（注意：PrismBench 默认在纯白/纯净背景下评估，不考察背景生成）。
    *   *打分示例：* 
        *   `1.0`: 
            - **动作/关系彻底丢失**：要求“A和B握手”，但两人只是毫无接触地并排站着（变成木头人）。
            - **纯文本道具遗漏**：要求“A在吃汉堡”，A生成得很完美，但画面里根本没有汉堡。
            - **状态丢失**：要求“A躺在地上睡觉”，但A是睁着眼站着的。
        *   `0.5`: 
            - **动作含糊**：要求“A吃汉堡”，A手里拿着汉堡但并没有做出“吃”的动作，只是拿着。
            - **次要道具缺失**：要求“A戴着帽子弹吉他”，A在弹吉他但没戴帽子。
    *   *🚫 防歧义边界：* 专门惩罚**“无中生有失败”（文本截断）**和**“木头人”（动作无视）**。走到这一步，核心人物肯定在场且没有串线，只惩罚缺失的动作细节。
    *   *对标现有指标：* **CLIP Score (CLIP-T) / ImageReward**。

*   **Class 0: 完美对齐 Perfect Alignment**
    *   *描述：* 上述 5 个错误维度全部得分为 `0.0`。即：人数对、没长歪、动作对、没串色、道具和交互动作完美贴合 Prompt 要求，且画面无明显崩坏。
    *   *打分示例：* 
        *   `0.0`: 要求“钢铁侠和美国队长在握手，钢铁侠左手拿着公文包”，画面中两人都完美呈现，未畸变，衣服颜色独立无污染，正在握手，且钢铁侠拿着包。完美达成目标。

### 2.2 标签设计与指标计算
对于这 11w 条数据，每个样本的 Label 输出一个包含 5 个错误维度得分的向量（例如 `[0.0, 0.0, 0.0, 0.5, 0.0]`，代表轻微特征泄漏）。这允许模型进行更平滑的回归学习，而不是生硬的 One-Hot 分类。

**为什么我们需要 6 个类别？（分类的学术意义与核心贡献）**
很多 Reviewer 可能会问：“既然 CLIP 和 DINO 只是一个总分，你们为什么要搞这么复杂的 6 类诊断体系？” 答案是：**这正是 LENS 超越现有指标的核心护城河。**
1.  **打破“黑盒打分”**：CLIP 给一张图打 0.6 分，没人知道为什么。LENS 不仅能给出一个偏好总分（Score Head），还能通过这 6 个类别（Classification Head）告诉你**具体错在哪里**（例如：80% 错在实体缺失，20% 错在串色）。这为未来的文生图模型优化指明了具体方向，这叫**“可解释性评估 (Interpretable Evaluation)”**。
2.  **强制特征解缠 (Forced Disentanglement)**：在多任务学习（MTL）中，这 6 个类别的分类损失起到了**极其强大的正则化作用**。如果模型只需要预测一个总分，它很容易走捷径（只看背景或只看某一个主体）。但因为 LENS 被强制要求同时预测“是否串色”、“是否错位”、“是否畸变”，它的交叉注意力（Cross-Attention）**被迫**深入到每个主体的边界和纹理细节中。换句话说，这 6 个分类是逼迫模型“认真看图”的紧箍咒。

**如何利用这 6 个分类算指标？**
*   **Error Rate Distribution (错误率分布)：** LENS 会统计一个模型在 N=2,4,6,8 时，触发 Class 1-5 的百分比。
    *   *例如：* MOSAIC 在 N=8 时，Class 5（实体缺失）高达 80%；而 Gemini 在 N=8 时，可能只有 10% 的 Class 5，但有 30% 的 Class 2（特征泄漏）。这能极其直观地对比不同模型的短板！

## 阶段 3：模型训练 (LENS)

LENS (Localized Entanglement Navigation and Scoring) 是一个轻量级的指标模型（例如 Qwen3.5-9B），在 PrismBench 的 10w 银集上进行微调，以同时预测连续的偏好分数和离散的错误类别。

### 3.1 架构：双头多任务学习 (Dual-Head MTL)
我们在 VLM backbone 的最后隐藏层状态上附加了两个头（Heads）：
1.  **分数头 Score Head (回归)：** 输出一个标量偏好分数。
2.  **分类头 Classification Head (分类)：** 输出 4 个错误类别 (0, 1, 2, 3) 的 logits。

### 3.2 孪生网络训练策略 (Siamese Network Strategy)
为了防止模型学习到虚假的上下文相关性（"聪明汉斯"效应 Clever Hans effect，比如将复杂的背景与高分相关联），我们在图像对上使用孪生网络的方法进行训练。

*   **输入 (Input)：** Image A（Gemini 好的图片）和 Image B（MOSAIC 差的图片），两者都是从**同一个** Prompt 生成的。
*   **前向传播 (Forward Pass)：** 两张图像独立地通过**同一个**共享的 VLM backbone 以提取特征嵌入（embeddings）。
*   **Loss 1 (排序损失 Ranking)：** 嵌入特征进入分数头。我们应用**边距排序损失 (Margin Ranking Loss)**。如果伪标签表示 Image A 优于 Image B，但 $Score(A) < Score(B) + margin$，则该损失会惩罚模型。
*   **Loss 2 (分类损失 Classification)：** 嵌入特征进入分类头。由于我们采用了三级打分制（包含 `0.5` 软标签）和多标签的可能性，传统的 Cross-Entropy Loss（仅适用于互斥单分类）不再适用。我们改用 **BCEWithLogitsLoss (Binary Cross Entropy with Logits)**。该损失函数独立计算 4 个类别的二元交叉熵，能够完美兼容 `0.0`, `0.5`, `1.0` 的连续概率目标。
*   **总损失 (Total Loss)：** $\mathcal{L}_{total} = \lambda_1 \mathcal{L}_{rank} + \lambda_2 \mathcal{L}_{cls}$

*为什么这样有效：* 分类损失起到了强大的正则化作用。为了正确识别“特征泄漏”与“语义错位”，backbone 的交叉注意力（cross-attention）**必须**聚焦在主体及其边界上，从而迫使模型忽略无关的背景像素。

### 3.3 标签质量保证 (Label Quality Assurance)
在使用 10w 条 VLM 伪标签 (Silver Set) 训练模型时，Reviewer 必然会质疑：“如果训练集的标签本身就是错的，模型怎么可能学好？（Garbage In, Garbage Out）”。为了保证 Silver Set 的绝对高质量，我们采用了以下过滤与蒸馏策略：

1.  **Teacher-Student 强弱代差蒸馏**：我们绝不使用 Qwen-9B 去标注 Qwen-9B。打标的 Teacher VLM 采用的是参数量或能力远超 Student 的顶尖闭源/超大开源模型（如 GPT-4o 或 Qwen-VL-Max 72B）。利用大模型的“慢思考”能力生成高质量标签，然后蒸馏给 9B 的小模型（LENS），使其具备专一的快速推理能力。
2.  **思维链 (CoT) 与多轮一致性校验 (Self-Consistency)**：在自动打标时，我们不让 Teacher VLM 直接输出分数，而是要求它先“数人头、找位置、看颜色”，最后再输出打分。此外，对同一张图片进行两次不同温度（Temperature）的打标，如果两次得出的分类结果严重不一致，则将该样本视为“高不确定性噪声”并直接从训练集中剔除。
3.  **强制锚点与清晰边界 (Hard Anchors)**：在孪生网络（Siamese）的 Pair 构造中，我们**保证 Image A 和 Image B 之间必须至少有一个明确的 `1.0` 差异**（例如：A是 `0.0`，B必须是 `1.0`）。过滤掉两张图全是 `0.5` 的模糊样本，确保输入给 LENS 训练的都是对比极其强烈的“清晰错误”，让模型通过对比学习（Contrastive Learning）抓取到绝对的差异特征。
4.  **人类基准校准 (Human-in-the-loop Calibration)**：在全面生成 10w 银集之前，我们会让 Teacher VLM 先在 500 条人类打标的金集上进行预测。只有当 Teacher VLM 与人类专家的一致性（Agreement Rate）达到 85% 以上时，才开始大规模自动化打标。这种“先考老师，再教学生”的策略从根本上保证了训练分布不偏离人类偏好。

### 3.4 数据集划分策略 (Data Split Strategy)
为了绝对保证学术诚信（防止数据泄漏）并兼顾训练效率，我们将总计 11 万条数据（10w 银集 + 1w 金集）进行如下严格划分：

*   **训练集 (Train Set)：约 100,000 条**
    *   *来源：* 纯自动标注银集 (Silver Set)。
    *   *用途：* 用于 Siamese MTL 架构的参数更新和梯度反向传播。
*   **验证集 (Validation Set)：约 2,000 条**
    *   *来源：* 纯人工标注金集 (Golden Set) 随机抽样。
    *   *用途：* 仅用于训练过程中的 Early Stopping（早停）和超参数调优，**绝不参与训练**。
*   **测试集 (Test Set)：约 8,000 条**
    *   *来源：* 剩余的纯人工标注金集 (Golden Set)。
    *   *用途：* 绝对隔离的 Held-out 数据集。用于产出论文中最终汇报的性能指标（Kendall-Tau, Pearson, F1-Score）。该集合在模型开发完成前**绝对不可见**，以证明模型真实的 Zero-Shot 泛化能力。

### 3.4 训练与评估框架 (Frameworks)
*   **深度学习框架：** `PyTorch 2.x`
*   **模型库与分布式训练：** 
    *   使用 Hugging Face `transformers` 加载 Qwen3.5-9B backbone。
    *   使用 `peft` 库应用 LoRA / QLoRA 进行高效微调（Parameter-Efficient Fine-Tuning），极大降低显存开销。
    *   使用 `DeepSpeed` (ZeRO-2/3) 或 `accelerate` 进行多卡分布式并行训练。
*   **评估指标计算框架：**
    *   *回归指标 (Score Head)：* 使用 `scipy.stats` 计算 Kendall-Tau 和 Pearson 排序相关性系数。
    *   *分类指标 (Classification Head)：* 使用 `scikit-learn` 计算 Accuracy 和 Macro F1-Score。

## 阶段 4：模型发布与 Hugging Face 托管 (Deployment)
为了让整个开源社区都能轻松使用 LENS 评测他们的模型，我们设计了极简的权重保存与托管策略。

### 4.1 权重保存机制 (Save Mechanism)
LENS 模型本身包含了一个庞大的 VLM backbone (Qwen3.5-9B)。为了**避免上传几十 GB 的冗余文件**，`lens/model.py` 中实现了自定义的 `save_pretrained()` 方法，它仅保存增量参数：
1.  **`lens_heads.pt`**: 仅约 20MB。包含了我们自己设计的 Score Head 和 Classification Head 的权重。
2.  **`lora_adapter/` (可选)**: 仅约 50MB。如果你在训练时开启了 `--mode lora`，这里会保存 PEFT 的 LoRA 增量权重。
3.  **`lens_config.json`**: 记录了依赖的基础模型 (`Qwen/Qwen3.5-9B`) 以及 Head 的分类维度等元数据。

当 `scripts/train.py` 运行结束时，上述三个文件会自动保存到 `outputs/LENS-v1-[mode]/` 目录下。

### 4.2 如何上传到 Hugging Face (HF Hub)
将训练好的 LENS 模型分享给社区非常简单：

1.  在 Hugging Face 创建一个模型仓库，例如：`your-username/LENS-Qwen3.5-9B`。
2.  将 `outputs/` 目录下的那三个文件（`lens_heads.pt`, `lora_adapter/`, `lens_config.json`）直接拖拽上传到你的 HF 仓库。
3.  在你的模型卡片 (Model Card/README) 里提供一段简单的加载代码，其他人就可以通过一行代码调用 LENS 了。因为我们保存了 config，其他人的代码会自动从 HF 官方下载原本的 Qwen 权重，并把你的 Head 缝合上去，即插即用！
